# Plain edit CPU profile

This is diagnostic evidence from HEAD 834c5cf, with a temporary named helper
around plain growing state updates. The helper uses the same transaction as
preview-growth.test.ts. Footnote-route transactions do not call the helper.
The helper was removed after the profile. The app source did not change.

plain-worker.cpuprofile.gz is the complete worker profile. profile.log retains
all twelve routes and all 240 exact-source and complete-decoration checks.
summary.json is generated by profile-summary.mjs. Attribution uses call
ancestry and excludes setup, footnote routes, fresh oracles, dirty comparison,
DOM, and garbage collection with no helper ancestry. These are CPU samples,
not individual edit times or native frame measurements. Categories have
priority in script order; nested work belongs to the first matching category.

Language parsing has 64.2% of helper samples. This does not identify the YAML
wrapper as the cause. The next inactive experiment changes only that wrapper,
with separate unprofiled clocks and complete source/decorations checked.

Apply instrumentation.patch to HEAD 834c5cf to reproduce the named boundary.
Use Node --cpu-prof with the growth benchmark. Run profile-summary.mjs with
the worker profile path to generate the summary. The script accepts gzip.

The wrapper/direct timing logs are separate unprofiled runs. BENCHMARKS.md
records all twelve routes and their limits. The varying results give no
consistent direct-parser gain. Keep the app language unchanged.
