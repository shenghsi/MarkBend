# Note-bearing edit CPU profile

Baseline e66f36f. macOS arm64, Node 22.23.2, jsdom, one worker. Production code
is unchanged. The fixture is the 1 MiB note-bearing growth document: a reference
at the start, repeated headings and formatted paragraphs, and a definition at
the end. Each start/middle/end route has twenty growing Z / 中 word insertions.
The first edit is retained. No other project tests or builds ran during profiling.

The inspector starts immediately before each edit and stops before its oracle.
Raw profiles include inspector overhead. summary.mjs accepts only samples with
applyNoteGrowth ancestry, which contains the state transaction and dirty source
comparison. Setup, fresh source/decorations checks, inspector calls, DOM, native
input, and screen frames are excluded. Unattached GC samples are reported
separately. Category priority is the script order; nested work belongs to its
first matching category. CPU samples are not elapsed edit times. The 1 ms
sampling interval, inspector overhead, and GC limit precision.

All sixty exact-source and complete-decoration comparisons pass. Every edit
publishes a complete tree. Every route uses full preview for all twenty edits.
The footnote model has a new object identity after every edit. This does not
mean full footnote parsing: mapStableSpans appears in the raw call stacks and
produces mapped models with new identities. The identity field measures only
object reuse. No latency or native-frame claim follows from these profiles.

| Edit location | Decoration construction | Cached preview collection | Language parsing | Footnote model |
|---|---:|---:|---:|---:|
| start | 41.67% | 27.80% | 16.65% | 6.27% |
| middle | 43.22% | 30.33% | 21.44% | 3.42% |
| end | 41.52% | 27.85% | 24.55% | 4.61% |

Preview construction and collection dominate these samples. The next candidate
must reduce full preview work while preserving global note numbers, definition
contents, source ranges, selection reveal, and history. Widening plain index
eligibility without those checks is insufficient. Structural/resource edits
and uncertain parser ranges still require full construction.

raw-profiles.tar.gz contains all sixty generated profiles. profile.log records
the route checks. summary.json is generated by summary.mjs. To reproduce:

```sh
profile_dir=$(mktemp -d /tmp/markbend-note-profile.XXXXXX)
MARKBEND_NOTE_PROFILE=1 MARKBEND_PROFILE_DIR="$profile_dir" npx vitest run tests/performance/note-profile.test.ts --pool=threads --maxWorkers=1
node tests/performance/experiments/note-profile/summary.mjs "$profile_dir"
```

Use an empty temporary directory for each run. Profiling can take two minutes
because independent assertions inspect every decoration after each edit.
The opt-in test stays outside the app and ordinary test runs.
